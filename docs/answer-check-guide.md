# 回答草稿格式与字面引用核验

更新日期：2026-10-12（Asia/Shanghai）。本次没有模型调用、模拟模型服务或付费请求。
测试使用手写的草稿作为候选；接口核验草稿，不替用户生成答案。

## 1. 本次检查与未检查的内容

检查草稿的结构、引用编号是否属于当前证据包、quote 是否是对应 text 中的连续原文，
然后由服务器查表补全文档编号、名称、物理页和引文字符区间。拒绝模型或调用者自行
提供页码、文件路径等来源字段；引用必须放在 citations，不手写在回答句子的 [E1] 中。

不检查句子是否被引文支持、推理是否成立、事实是否正确、证据是否完整或拒答是否合理。
返回始终包含 semantics_verified=false 和 checks_scope=format_and_literal_citations。
真实但无关的引文也可能通过此检查，不能因此把“格式与字面引用通过”说成答案正确。
本次不自动回答或自动拒答，不把这些测试当作模型能力评测或提示注入防护验证。

## 2. 两种指纹各解决什么问题

context 响应新增 context_id，其他既有字段保持原样。

- source_sha256：原 PDF 字节的指纹，用于来源文件版本核对。
- context_id：问题、方法、K、预算、来源指纹、证据登记表及包内容的规范 JSON 指纹。
  同一 PDF 上换问题、预算或证据选择，都可能使 context_id 改变。

两者都不是密码、认证令牌或签名，不能替代鉴权。E1 只在这一份包内有效。
check-answer 从磁盘重新检索/校验并重新打包；先比对 context_id，再做引用核验。
调用者只能提交预期 ID 和草稿，不能提交自己的证据包覆盖服务器来源。
旧包无效时应重新获取 context，而不是手动把新 ID 填到旧草稿里蒙混通过。

## 3. 在 /docs 验收

如果服务没有自动重载，先重新启动，再打开 /docs。
先调用 POST /documents/{document_id}/context：

```json
{
  "query": "复数三角不等式",
  "method": "normalized",
  "k": 10,
  "max_context_chars": 6000
}
```

复制响应中的 context_id，并从 evidence 中的 E1.text 复制一段最多 1000 字符的连续
原文，保留大小写、标点、空格和换行。引文不能只含空白，也不要按 PDF 原图自行改写。
此处比较的是提取文本，排版/公式失真仍需原 PDF 人工核对。

再调用 POST /documents/{document_id}/check-answer。下面两处占位值必须替换，不能原样提交：

```json
{
  "query": "复数三角不等式",
  "method": "normalized",
  "k": 10,
  "max_context_chars": 6000,
  "context_id": "替换为刚才返回的64位指纹",
  "draft": {
    "decision": "answer",
    "claims": [
      {
        "text": "这里填写一条待核验的回答句子，不手写引用编号。",
        "citations": [
          {
            "citation_id": "E1",
            "quote": "替换为E1.text中的连续原文"
          }
        ]
      }
    ]
  }
}
```

问题和所有检索/预算参数必须与上一请求一致。默认值为 original、K=5、预算6000，
不要获取 normalized/K=10 的包，却在核验请求里漏掉这两个字段。

可做三个实验：正常引用通常 passed；将 citation_id 改为 E999 应 rejected；保持旧
context_id 但更换问题/参数应 HTTP 409。将 quote 改成不在 E1 中的文字也应 rejected。
这只是核验操作验收，不是对测试句子的语义认可。

## 4. 回答与拒答的格式规则

回答草稿 decision=answer 至少有一条 claim，每条有1～5个结构化引用，最多20条claim。
每条句子最多2000字符，单条引文最多1000字符。不得同时携带 reason。
同一句子的同一编号＋同一引文重复出现会拒绝；同证据不同引文或跨句复用则允许。
句子不得插入 [E1]、[ E99 ] 等引用标记，以免绕过结构化登记；引文本身保持原文不变。

拒答草稿只需要：

```json
{
  "decision": "refuse",
  "claims": [],
  "reason": "这里说明候选草稿为何拒答，不插入引用标记。"
}
```

拒答必须有非空理由，不能同时有回答claims。即使包里有证据，拒答格式也可能通过，
因为本层不判断拒答是否必要。反过来，no_matches 或 budget_exceeded 的空包不能通过
answer 的引用核验，但程序也不会擅自生成一条“文档没有答案”的拒答。

## 5. 返回值与 HTTP 状态

HTTP 200 表示核验过程完成，结果看 status：passed 或 rejected，不表示答案正确。
rejected 返回 issues（代码、句子序号、编号等），claims 为空，不把部分通过的句子
冒充完整合法答案交付。语法字段不合法由请求模型返回422；包/来源改变返回409；
未知文档404；超过原检索加载上限413；读取异常500且不泄露磁盘路径。

passed 的 claims 中每条引用带服务器来源与引文位置：

- evidence_start_char/evidence_end_char：原证据块在页面中的位置。
- quote_start_char/quote_end_char：本次引文在页面中的位置。
- 若同一句引文在该块内出现多次，采用第一次出现的位置，不宣称知道模型指的是哪一次。
- 使用 Python 字符数和 [start,end) 区间，不是 UTF-8 字节、浏览器字符索引或 PDF 坐标。

引文匹配不会自动忽略大小写、合并空格、修复标点或公式；失败时应核对原文，而不是
把“存在于另一段”当成当前 E 编号的有效引文。下一步显示页面时也需按文字处理草稿，
不能把任意回答当 HTML 执行。
