# 编号证据上下文：检索与模型之间的准备步骤

更新日期：2026-10-12（Asia/Shanghai）。本次不调用模型、不产生模型费用，不保存新的数据文件。
主工作台仍执行原 search 流程；新 context 接口先在 /docs 中独立验收。

## 1. 为什么要独立打包

搜索返回按 BM25 排序的原文片段。后续问答还需要一份有大小限制、可用编号引用、
能反查来源的数据包。evidence_context.py 只做这一层，不改变分词、排序、分块或来源文件。
它不是提示词、答案生成器、重排序器或证据充分性判定器。

## 2. 接口使用

服务重新加载后，在 /docs 打开 POST /documents/{document_id}/context，点击 Try it out。
document_id 使用工作台当前文档区的完整 32 位编号，不是左侧列表的 8 位缩写。
文档必须已解析。正文示例：

```json
{
  "query": "复数三角不等式",
  "method": "normalized",
  "k": 10,
  "max_context_chars": 6000
}
```

默认参数仍沿用 SearchRequest：original、K=5；新增字符预算默认为 6000，范围 128～20000。
先复用原 DocumentSearchService 读取和校验源文件、上传记录、报告、页面与分块，然后打包。
如果文档不存在、未解析、来源改变或参数不合法，分别沿用 404/409/422 等明确错误。
没有默认 lecture 回退，不把不同编号的同名文档混在一起。

## 3. 打包规则

先检查所有候选的字段、文档编号/名称、字符长度与区间、返回数量及重复位置的一致性。
纯打包函数检查的是结果结构与内部一致性；真实文件的来源检查由此前的检索服务完成。
预算装不下的候选也要检查，不能借“会被省略”掩盖跨文档或损坏来源。

按原检索顺序逐块考虑：

- 同一编号、物理页和字符区间的重复块只保留第一次；同位置不同原文视为错误。
- 实际收录的片段顺次编号 E1、E2……，同时保留原 retrieval_rank 与 BM25 分数。
- 预算容纳不下整块时省略该块，继续考虑之后更短的候选，不截断原文、不改字符区间。
- 不自动合并邻块或补全证明；整块保留不代表数学论证本身已经完整。
- 零/负 BM25 分数不作为拒答或过滤阈值；分数不是置信度。

E1 等编号只在当前证据包内有效，不是跨查询的永久编号。稳定来源仍是文档编号、
source_sha256、物理页号、start_char 和 end_char。不同问题或预算下 E1 可能指不同片段。

## 4. 返回值如何阅读

- evidence：完整引用登记表，每项有 citation_id、原检索排名、分数、文档编号、名称、
  物理页、字符区间和完全保留的 text。
- context_id：当前问题、参数和证据包的指纹，用于后续草稿核验绑定；不是认证令牌。
- context_text：证据的 JSON 字符串，只包含编号、文件名、物理页、字符区间和原文；
  没有模型指令，且不把长编号与分数放进模型侧证据文本。JSON 解析后 text 与原文一致。
- retrieved_count：这次 Top K 候选数，不是整份文档的全部匹配数量。
- included_count / omitted_count：实际收录/省略数量，二者相加等于 retrieved_count。
- omitted：省略候选的原排名与位置，reason 为 duplicate 或 budget_exceeded。
- used_chars：len(context_text)，包含 JSON 引号、转义字符、编号、来源字段与格式。
- max_context_chars：只限制 context_text，不限制整个 API 响应长度，也不包含问题或未来
  系统指令。它是 Python 字符预算，不是模型 tokenizer 计算的 token 数或费用上限。

context_text 在外层 JSON 中显示为带转义的字符串是正常编码，不是原文被替换。
后续读取响应并对 context_text 做 JSON 解析，即可得到原文字段。
数据包中原文仍是不可信文档内容；JSON 包装只保证格式，不能宣称防住提示注入。
这一步没有执行文档内的命令，也没有向模型发送这些内容。

## 5. 三种状态不是回答判断

- ready：至少一块被收录。可能仍省略部分候选，不表示证据充分、相关或答案正确。
- no_matches：这次查询没有返回候选，不表示 PDF 中必然没有答案。
- budget_exceeded：存在候选但没有整块能装入预算，不应冒充“没找到证据”。

后两种情况下 context_text 为空、used_chars 为 0，但 retrieved_count 可帮助区分原因。
当前不返回生成式 answer/refusal，也没有核验未来模型的引用或事实。
