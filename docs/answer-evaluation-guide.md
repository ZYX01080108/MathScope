# 已核对公式模式：回答与拒答开发评测

日期：2026-10-15。本步把手动验收变成可重复的脚本，但没有替用户运行真实收费评测。
默认只做免费预检；预检通过不代表模型答对，默认报告中的行为分数保持 null。

## 1. 这次评测什么

固定六个开发案例在 docs/reviewed_answer_cases.json，针对当前唯一核对记录 FR001：

| 编号 | 内容 | 当前核对片段下的预期 | 是否可能调用模型 |
|---|---|---|---|
| RA001 | 三角不等式何时取等号 | answered，选择 FR001 | 是 |
| RA002 | 同一等式充要条件的改写问法 | answered，选择 FR001 | 是 |
| RA003 | 要求取等号条件的完整证明和逐步推导 | refused，只有审阅结论而没有审阅证明 | 是 |
| RA004 | f(z)=|z|² 在哪里复可微 | refused，无对应审阅注释 | 否 |
| RA005 | Riemann 映射定理的完整证明 | refused，无对应审阅注释 | 否 |
| RA006 | 人工构造的无匹配字符串 | refused，本地安全控制项 | 否 |

RA003 检验一个重要区别：模型可能逐字引用了正确结论，但用户要的是完整证明。
这种 answered 仍不符合标注。RA004/RA005 的拒答仅针对当前已核对证据，不声称
原始讲义没有答案。模型拒答本身也可能收费：RA003 需要模型判断结论是否够用。

这六题只有一个知识点，两个回答题是同义改写，一个题是人工控制项。它们全是
开发案例，不是独立留出测试集，不能据此宣布通用数学正确率、泛化能力或正式评测结论。

## 3. 推荐先运行：免费预检

先在原服务终端 Ctrl+C 停止，并启动新代码，付费服务仍不使用 --reload/多 workers：

```powershell
.\.venv\Scripts\python.exe -m uvicorn src.api:app --host 127.0.0.1 --port 8000
```

在第二个 PowerShell 终端进入 D:\MathScope项目，运行（不需要复制密钥到新终端）：

```powershell
.\.venv\Scripts\python.exe -m src.evaluate_answers --document-id f73e1265fc5242829509031e208d7256
```

默认只对本机 /reviewed-context 发起六次免费查询，不调用 /answer-reviewed 或模型。
它会验证源 SHA256、实际核对记录及版本、每题可用记录是否与固定标注一致。
原数据未变时，前三题各有 FR001，后三题无可用核对片段；可能收费的模型分支共 3 题。

默认报告写到 reports/answer-evaluation-<唯一编号>.json，不覆盖旧报告。若要指定路径：

```powershell
.\.venv\Scripts\python.exe -m src.evaluate_answers --document-id f73e1265fc5242829509031e208d7256 --output reports/answer-preview-first.json
```

已存在的路径会明确失败，不会追加调用或覆盖。预检报告应有：

- mode=preview，status=preview_completed；
- preflight_completed_count=6，planned_model_branch_cases=3，planned_local_branch_cases=3；
- completed_case_count=0、fully_executed=false；
- behavior_match_rate 等分数为 null，实际回答显示“未评测”。

如果源文件、分块、核对注释或检索配置变化，预检可能失败。请先检查变化原因并
重新核对标注，不要只为“跑通”而随意改指纹/预期。HTTP 404 也可能表示旧服务尚未
加载新接口；先重启自己的服务，不重传/删除原文档。

## 4. 可选：真实行为评测，整轮最多预留 3 次模型尝试

确认免费预检符合预期、服务已启用 DeepSeek、账户余额和当前服务调用额度允许后，
才执行以下命令。这会发送问题和核对结论到 DeepSeek，可能收费：

```powershell
.\.venv\Scripts\python.exe -m src.evaluate_answers --document-id f73e1265fc5242829509031e208d7256 --live --allow-paid --max-model-calls 3
```

三项必须同时明确填写；默认不推断为同意收费。脚本先完成全部预检，再检查上限，
本轮上限只能设 1～3。默认六题需要预留 3 次，若填 1 或 2，则不发送任何回答请求。
无核对片段的三题仍会调用本机回答接口验证本地拒答，但不调用模型。

脚本使用已经运行的服务，共用其调用额度，不创建新的模型客户端、不读取密钥、
不自动重启服务、不扩大配额、不重试。若服务只剩不足三次，可能得到 429 并停止。
更新代码需要重启时，本地计数会重置，但平台历史费用不会取消；不要靠反复重启
扩大调用量。次数上限不是账户人民币 20 元硬上限，账单仍以平台为准。

每个回答请求携带预检时的 expected_reviewed_context_id。服务在调用前发现证据
变化时返回 409，不进入模型分支；模型调用后仍会再次检查来源。检查之后的并发
变化不可能撤销已经发出的调用，不能把来源检查理解成任何异常都免费。

任何 HTTP/超时/响应契约错误会停止后续题目，不自动重跑整轮。错误时的
model_call_reservations 是保守预留的尝试数量，不是实际已收费次数。比如调用前
因版本变化返回 409，可能预留了一次但真正模型调用为零；超时则可能已经收费。

## 5. 报告怎么看，为什么这些比较成立

每题保留：预期 answered/refused、可用记录、预览版本、真实接口结果、实际状态、
所选核对记录及 behavior_match。比对之前还会检查源文件、原始/核对证据指纹、
逐字结论、注释引用与位置、token 用量是否符合返回契约，异常不会混入成功分数。

对当前标注：

1. answered 题要实际返回 answered，且选择完整的预期核对结论、引用正确记录。
2. refused 题要实际返回 refused，格式合法且没有 claims。
3. rejected 表示草稿被安全拦下，不是用户得到了一次合适的拒答，因此不算 refused 题通过。
4. 错误/超时/未运行不是“答错某条数学事实”，也不是“正确拒答”，单独记录。

六题全部收到合法结果时才给出以下行为匹配率：

- behavior_match_rate：匹配预期行为的题数 / 6；
- model_branch_match_rate：前三个可能调用模型的案例单独统计；
- local_branch_match_rate：后三个本地无证据控制项单独统计，避免它们掩盖模型表现；
- answer_case_match_rate：两个应回答案例的匹配率；
- refusal_case_match_rate：四个应拒答案例的匹配率。

例如，模型对 RA003 只复述结论，即使注释引用正确，也判该题不匹配；反过来，
出现 rejected 只证明守卫拦住了草稿，并不证明模型给出了合理拒答。预检只验证
输入条件，根本没有观察模型输出，所以不能给回答/拒答分数。

known_token_usage 只合计收到合法返回时已知的用量；错误/超时可能有未知用量，
不能视为完整账单或直接换算成确定人民币消费。回答错误或 rejected 的调用同样可能收费。
退出码 0 只代表预检或整轮执行完成，不代表六题全部通过，必须看分数和逐题记录。

程序按人工标注计算可观察行为，不自动证明数学、判断拒答理由的充分性或保证
问题相关性。审阅记录的正确性与完整性也仍需人工复核，semantics_verified 仍为 false。

## 6. 保存、隐私与边界

只允许带明确端口的本机 HTTP 地址，默认 127.0.0.1:8000；不跟随重定向、不继承
代理，不允许远程主机、地址路径、查询串或 URL 凭证。不在报告中保存密钥，
报告会包含问题、核对注释和回答，已由 reports/ 的 Git 忽略规则排除。

报告在请求前以独占方式创建，每个可能收费请求前记录预留状态并落盘，逐题更新
本次创建的文件；写盘失败就停止，不覆盖以前的报告。这不是数据库事务或完整
断电恢复机制；中断报告可能停在 pending，必须人工检查，不支持自动续跑。
