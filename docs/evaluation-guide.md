# 十题开发评测 v0.1：题目、程序改动与验收

## 当前状态与标注口径

原有 Q001-Q003 不改查询和目标块。新增 Q004-Q010 后，共 10 题：8 道可回答，2 道证据不足。
新增题已由助手核对提取文本、完整 PDF 渲染页、物理页号和对应字符区间，仍建议用户复核。
所有题属于开发集，不是独立留出测试集；标注的是足以支持答案要点的目标块，未穷尽其他相关块。
因此输出名称是目标覆盖率、目标 RR/MRR 和目标 nDCG，而不是正式 Recall 或回答正确率。

## 文件职责与改动目的

- `docs/eval_cases.json`：问题、预期行为、答案要点、目标块和短证据摘录。新增题覆盖不同章节，以及跨块和目录干扰场景。
- `docs/eval_manifest.json`：固定 PDF、页面文件、分块文件的 SHA-256，记录解析版本、分块规则和标注范围。
- `src/evaluation_runner.py`：先验证指纹、块与原页切片、标注位置和摘录，再调用同一个 BM25Retriever，计算指标并组成报告对象。
- `src/compare_bm25.py`：负责命令行参数、输出和保存 JSON；不再重复实现指标统计。
- `tests/test_evaluation_runner.py`：用临时小语料验证数据变更、错标证据、错误来源、负例排除和保存行为。测试不依赖 lecture.pdf。
- `reports/`：每次运行一份新报告。已加入 .gitignore，避免大量运行产物进入 Git。精选结论仍可写进 docs/experiments。
- `README.md`：补齐环境、测试、检索和评测的运行入口。

## 运行和查看

在项目根目录、已激活的虚拟环境中运行：

```powershell
python -m unittest discover -s tests -v
python -m src.compare_bm25
```

程序会打印 10 题，其中计分 8 题、证据不足 2 题，并显示报告的完整路径。
默认是 `reports/evaluation-<run_id>.json`；重复执行会生成另一份，不覆盖旧报告。
也可指定一个尚未存在的文件：

```powershell
python -m src.compare_bm25 --output reports/my-check.json
```

打开报告，按以下顺序阅读：

1. `dataset`：10/8/2 的数量、开发集身份及标注限制。
2. `input_fingerprints`、`runtime`：具体数据、题集、清单、源码指纹、包版本与 Git 状态。
3. `methods[*].cases`：逐题查询、目标排名、全部候选的来源和分数、每个 K 的命中及缺失目标。
4. `methods[*].summary`：同一方法、同一 K 下的按题宏平均；两道证据不足题不进入分母。

`query_ms` 和 `index_build_ms` 是一次执行的实测 wall-clock 耗时。查询时间包括分词、评分、排序和结果构造，
不包括 PDF 解析和文件读取。它们不是 P50/P95；冷暖缓存未控制，不能据此声称性能提升。

## 重要边界

改 PDF、重新解析或改分块后，旧清单应阻止继续沿用旧标注。不要为了绕过报错只更新哈希；
必须重新核对证据位置、答案要点和区间，再新建数据集版本。
两道证据不足题会保留检索结果作为人工分析材料，但没有回答层，所以报告不自动判定拒答成功。
更多简单题带来的总体平均值变高，不代表算法发生了提升；算法比较必须使用同一版题集。
