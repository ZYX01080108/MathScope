## 1. 打开页面

从项目根目录启动；已有未开启自动重载的服务需先在自己的终端按 Ctrl+C 停止，再启动。
不要为启动页面停止不属于本项目的服务，端口被占用时可选择另一个本地端口。

```powershell
.\.venv\Scripts\python.exe -m uvicorn src.api:app --reload --host 127.0.0.1 --port 8000
```

浏览器访问 http://127.0.0.1:8000/，不是直接双击 index.html。
HTML、CSS、JavaScript 和业务 API 来自同一个服务，页面用相对地址发送请求；
没有独立前端服务器，没有 npm 安装或构建步骤，也不需要 Node 来运行页面。
/docs 继续作为开发者接口测试页面。/、/ui/app.css、/ui/app.js 是页面资源地址，
不计入业务接口，且不出现在业务 OpenAPI 清单中。原 7 个业务接口保持兼容，
原文件只读接口见第 6 节。后续增量目前共有 14 个业务接口，使用方法见
[证据打包说明](evidence-context-guide.md)；主工作台搜索流程没有改变。
DeepSeek 回答接口独立在 /docs 验收，见 [模型接入指南](deepseek-guide.md)。若启用付费
模型，首次验收请按该指南启动，不使用本节的 --reload，以免自动重启重置调用次数。
公式提取风险检查与不收费的验收见 [公式质量说明](formula-quality-guide.md)，不改页面检索流程。
单条公式核对注释的免费预览及受限回答见 [核对片段指南](reviewed-formula-guide.md)，
目前仍从 /docs 单独操作，不在本页面搜索时隐式调用模型。

## 2. 操作流程

1. 上传或选择：左侧列出当前配置数据目录里的文档，每页 20 份，按编号而非上传时间排序。
   上传仅保存文件，成功后自动选中返回的编号；新文档不一定在当前分页内，当前文档区仍会显示它。
2. 解析：只有有效的 uploaded 文档可以解析。默认每块 500 个 Python 字符，按物理页分块，
   不跨页。解析在请求中同步完成，页面显示等待，不提供虚构的进度百分比。
3. 搜索：选择已解析且有文本块的文档，输入问题，选择 original/normalized 和 K=1～20。
   页面默认 normalized；原 API 默认值不变。一次仍只检索一份文档。
4. 核对证据：查看原文、物理页号、页内字符区间 [start,end) 和 BM25 分数。
   分数不是概率或置信度，文本提取仍可能损坏公式。没有匹配并不证明文档没有答案，
   也不是自动拒答。证据卡片可在新标签页打开原 PDF 对应物理页，没有内嵌查看器、
   片段高亮或生成式回答。

浏览器只记住当前页面的选择和结果；刷新整个页面后要重新选择文档。
文件保存在后端磁盘，关闭页面不会删除。文件路径由 Settings 控制，不由页面指定。

## 3. 状态与失败处理

- 未选择、无文本块、invalid 或 incomplete 时不能搜索；parsed 时不能重复解析。
- 一个操作未结束时禁用相关控件，代码也拒绝重复启动同一轮操作。
- 切换文档清除旧证据；搜索失败（含本地参数错误）清除旧证据并显示“检索失败”。
- 刷新无法确认当前文档时取消旧选择，要求重新选择，不继续使用旧的可搜索状态。
- 上传/解析已经成功但随后列表刷新失败时，保留成功状态和编号，提示刷新而非重复提交。
- 网络中断时写入结果可能未知，请先刷新文档并核对状态，不要盲目再次上传或解析。

文件名、原文和错误信息使用 textContent 写入文字节点，不作为 HTML 执行。
页面资源有同源内容策略及禁止 MIME 猜测的响应头；这些措施不等于多用户安全、
完整 XSS 审计或公网部署保护。请继续只监听 127.0.0.1。

```powershell
node --check src/web/app.js
node --test tests/web/workspace.test.cjs
```

JavaScript 另有 21 项交互测试。
unittest 不会自动运行 JavaScript 测试，两条测试命令必须分别执行。
JavaScript 测试使用 Node 自带 node:test、vm 和小型 DOM/fetch 替身，无第三方 npm 包，

## 6. 打开原 PDF 与证据页（2026-10-12 增量）

选中有效文档后，当前文档区有“打开原 PDF”，尚未解析时也可使用。
检索结果各有“打开 PDF 第 N 页”，链接结构为：

```text
/documents/<document_id>/file?sha256=<source_sha256>#page=9
```

document_id 指定文档，不使用文件名定位；sha256 绑定该次检索的原文件版本。
#page=9 是浏览器处理的 URL 片段，不会发送给后端，也不是后端重新提取第 9 页。
页面发送的是 Python 提取时记录的、从 1 开始的 PDF 物理页号，不是讲义印刷页码。
浏览器不支持 PDF 内联显示、禁用了查看器或不识别跳页时，可能下载文件或从首页
打开；请根据证据卡片的物理页号手动定位，不应以此判定原文证据不存在。

后端只读取配置上传目录中的同编号 PDF 和上传 JSON。校验编号、路径、PDF 文件头、
大小及 SHA256，并按可选预期指纹核对后，直接返回本次已校验的字节快照，不重新打开路径。
PDF 最多读 10 MiB＋1 字节、元数据最多 64 KiB＋1 字节，用多读的 1 字节判断超限。
响应为 application/pdf 和 inline，文件名使用安全的编号；不解析、不写文件、不构建索引。
未知或缺失来源返回 404，损坏记录或版本冲突返回 409，原 PDF 超限返回 413。

当前返回完整快照，不实现 HTTP Range 分段响应；即使带 Range 请求也返回完整的 200。
每次读取与哈希有 CPU/内存成本，大小限制不等于并发请求资源隔离。
文件头校验不是 PDF 完整有效性或恶意内容扫描；此原型仍无用户鉴权或公网安全保证。
路径与符号链接检查不等于对恶意本机并发修改的操作系统级隔离。

新增 20 项接口测试、3 项链接交互测试，包含旧指纹拒绝、同大小替换拒绝、路径边界、
读后文件改变仍返回已验证快照、物理页号和安全新标签页属性。
用随机本机端口对现有 lecture 做了只读真实 HTTP 验收：证据物理第 9 页，原文件
接口为 200，返回 640294 字节，与原文件及证据 SHA256 一致；临时服务已停止。
这是文件传输与链接结构验收，尚未验证浏览器 PDF 显示或自动跳页，也没有新增依赖或提交。
