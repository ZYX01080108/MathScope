# 公式提取风险检查与回归案例

日期：2026-10-13。本步增加保护，不宣称已经恢复共轭横线或所有数学公式。

2026-10-15 后续增量：新增 [单条已核对公式模式](reviewed-formula-guide.md)，原始
回答的本风险门不变；新模式只使用独立审阅注释，不放行整页，也不覆盖原始文字。

## 1. 为什么加这一层

用户第一次真实模型调用完成：3484 个输入 tokens、240 个输出 tokens，总计 3724。
模型第一条要点把三角不等式的取等号条件写成 `zw ≥ 0`，而原 PDF 物理第 9 页
（印刷第 3 页）是 `z * conjugate(w)` 为非负实数。共轭横线是独立绘图指令，不在
pypdf 提取的字符中。原文字面引文通过，不代表提取结果保留了全部数学信息。

这个真实失败已记录为 tests/fixtures/triangle-conjugate-regression.json 的 MATH-F001，
绑定原文件 SHA256、物理页、错误句子、丢失符号的引文和实际观测的线段坐标。
另有 `z=w=i` 的反例：三角不等式取等号，但 `zw=-1`；正确的 `z*conjugate(w)=1`。

不能把所有 `zw` 全局替换成带共轭的形式：很多乘积本来就应是普通乘法，会制造新的错误。
本步不修改原 PDF、提取文本、分块、原文 offsets 或检索算法。

## 2. 做了什么

新增 src/formula_quality.py：从与当前证据相同版本的校验后 PDF 字节，检查本次
收录证据所在的完整物理页。识别简单的细短水平描边/填充条，作为共轭横线、分式
等可能无法由纯文本表达的风险信号；不是逐字公式识别器，也没有把横线分配给字符。

当前规则限定内容坐标下线宽 0～1、水平长度 2～80，填充条高度 0～1；只支持
平移矩阵。复杂变换、XObject/图像、剪裁、曲线、损坏数据等为 unassessed。
单页解码内容最多检查 2 MiB、最多 20000 条操作，超限不继续判成无风险。内容流
和操作需要先解码/解析再检查上限，因此不是 PDF CPU/内存的硬隔离。

| status | 含义 | 当前自动生成策略 |
|---|---|---|
| risk_detected | 检测到细短水平绘图痕迹，可能承载纯文本缺失的信息 | 拒答，不调用模型 |
| unassessed | 当前规则不能完成检查，或没有质量报告 | 拒答，不调用模型 |
| not_flagged | 该规则没有发现上述痕迹，不等于公式完整/数学正确 | 可以进入既有模型流程 |
| no_evidence | 没有收录完整证据，不读取原 PDF 做本检查 | 按既有无证据策略跳过模型 |

报告绑定 document_id、原文件 SHA256、context_id 和去重后的证据页列表。不能
拿另一份文档/问题的报告复用。客户端不能在 answer 请求里传入一个假的 not_flagged
报告来绕过。报告 text_modified 固定 false。

检测按整页而非按字符块进行，装饰线/下划线也可能触发，因此可能误报，并且会让
部分不依赖公式的问题也暂时拒答。这是明确的保守权衡，不是高精度的数学错误分类。
不能将第 9 页的 33 处绘图痕迹理解为 33 个错误或 33 个缺失共轭符号。
其他编码的符号丢失、上下标、根式、阅读顺序等可能漏检；not_flagged 从不保证无损。

## 3. 接口变化

新增 `POST /documents/{document_id}/quality`：只读、无模型调用，无需密钥或外发许可。
参数与当前 answer 检索参数一致：默认 normalized、K=10、6000 证据字符；最多 6000。
返回检查页、原因、痕迹数量以及 blocks_generation。总业务接口数从 11 增为 12。

`POST /documents/{document_id}/answer` 自动先执行这一检查，响应新增 quality。
有风险/无法检查时，返回 status=refused、check.claims=[]、需要核对的物理页，
generation.model_called=false、usage=null，不消耗新的模型尝试次数。
无标记证据才会执行既有模型调用；失败次数限额、来源再次核验与引用检查保持原样。

context、search、check-answer、解析文件和主工作台行为不变。特别是 check-answer
仍仅检查草稿格式和字面引用，不扫描原 PDF，也不判数学真假；不能把它的 passed
理解为质量检查已通过。semantics_verified 仍为 false。

## 4. 用户验收：先检查，不消费模型额度

1. 在原服务终端 Ctrl+C 停止，再按原命令启动新代码。当前终端的密钥环境变量仍
   存在时不必重新粘贴；新终端则需按 DeepSeek 指南重新配置。
2. 启用模型的服务仍不要加 --reload，不增加多 workers。重启会重置本地次数，
   不会撤销平台已用费用，也不是绕过预算的办法。

```powershell
.\.venv\Scripts\python.exe -m uvicorn src.api:app --host 127.0.0.1 --port 8000
```

3. 刷新 `http://127.0.0.1:8000/docs`。必须先确认看到新增 quality 接口；没有看到
   就不要再次点旧 answer，先检查是否仍在访问旧服务。
4. 展开 `POST /documents/{document_id}/quality`，编号填写当前已解析文档的真实 ID。
   原 lecture 的编号是 f73e1265fc5242829509031e208d7256，填写以下请求并执行：

```json
{
  "query": "复数三角不等式在什么条件下取等号？",
  "method": "normalized",
  "k": 10,
  "max_context_chars": 6000
}
```

对未变的这份原数据，预期 status=risk_detected、blocks_generation=true，第 9 页
short_horizontal_mark_count=33。本次检查证据页为 8、9、11、13、20、23、24、34；
这是本次查询的证据页，不是全书扫描。更换文档、参数或分块后不保证这些数值。

5. 可选：确认质量接口已经命中此风险后，再用原请求测试 answer（含 allow_external=true）。
   对同一来源和参数，预期 status=refused、quality.status=risk_detected、
   generation.model_called=false、check.claims=[]。此分支不产生新的模型调用。
   不要把所有 answer 请求都当成免费：换题、换文件或参数后可能进入模型分支。

不用重新上传、解析或删除旧数据，本次没有改原文字段。看到拒答是保护生效，
不是已经修复公式后得到正确答案；本题的自动生成能力暂时被阻止。

## 5. 验证记录和下一步

新增 28 项测试：图形几何、复杂内容/上限、来源绑定、真实 PDF 内容流的合成
夹具、错误句子仍可通过字面检查但质量门会阻止模型，以及数学反例。
合成夹具不需要私有讲义，也不构成对全部字体/公式的兼容性验证。
累计 319 项 Python 测试和 21 项 JavaScript 测试通过；版本检查、pip check 通过。

另外对真实 lecture 用独立 TestClient 实例只读验收：quality 命中第 9 页，answer
在模型 complete 被明确禁止的条件下返回拒答。原 PDF、上传元数据和三个解析文件
的 SHA256 前后相同。该实例独立于用户 8000 服务，其 calls_used=0 不表示用户账户
历史消费为 0。此步骤没有真实模型调用、额外费用、数据迁移、Git 提交或新依赖。

接入首次真实成功来自用户提供的返回；平台账单金额尚未核对。数学答案并未完全
验收。下一步需选定并验证可靠的公式恢复/人工审阅层，保留原始文本和来源映射，
再恢复这些风险证据的自动问答。若要将页图发送外部视觉/OCR 服务，需先另行确认
服务、图像外发范围和费用；本步没有执行任何外部 OCR 或图像模型调用。
